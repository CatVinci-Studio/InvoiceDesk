## 1. 简介

### 1.1 这是什么

智票是一款在你自己电脑上运行的发票整理工具。它把报销流程里最机械的四件事自动化：

| 你原来要做的                   | 智票做的                     |
| ------------------------------ | ---------------------------- |
| 一张张打开 PDF，抄号码、抄金额 | 批量读出全部字段             |
| 手工判断这张算差旅还是招待     | 按规则自动归类，规则你可以改 |
| 担心某张票上个月已经报过了     | 自动比对全部历史记录并标出来 |
| 往 Excel 里一行行填            | 一键导出，或直接填进公司模板 |

### 1.2 适用于谁

- 需要定期报销的个人
- 帮团队汇总报销的行政、助理
- 小微企业做账的人

### 1.3 明确不做的事

诚实地说清楚边界，比事后解释更有价值：

- **不做发票真伪查验。** 国家税务总局的查验平台有验证码，没有公开接口。智票做的是**一致性校验**（金额勾稽、号码位数、日期合法）和**重复报销检测**，并提供一键跳转到官方查验页。真伪存疑的票请自行查验。
- **不联网同步。** 没有账号，没有云端，没有多设备同步。数据只在这台电脑上。
- **不自动提交报销。** 它生成表格，提交流程是你和公司之间的事。
- **不保证 100% 识别率。** 皱掉的、盖章盖住数字的、复印了三遍的纸质票，谁都读不准。智票的设计原则是**读不准就明说**，而不是给你一个看起来很确定的错数字。

## 2. 安装

### 2.1 系统要求

| 平台    | 要求                                      |
| ------- | ----------------------------------------- |
| macOS   | 11 Big Sur 及以上，Apple Silicon 或 Intel |
| Windows | Windows 10 1809 及以上，64 位             |

Windows 需要 WebView2 运行时。绝大多数 Windows 10/11 已预装；如果没有，安装程序会提示。

### 2.2 下载与安装

到 [Releases](https://github.com/CatVinci-Studio/InvoiceDesk/releases/latest) 下载对应安装包：

| 平台                               | 文件名                             |
| ---------------------------------- | ---------------------------------- |
| macOS（Apple Silicon，M 系列芯片） | `Invoice Desk_0.0.2_aarch64.dmg`   |
| macOS（Intel 芯片）                | `Invoice Desk_0.0.2_x64.dmg`       |
| Windows                            | `Invoice Desk_0.0.2_x64-setup.exe` |

不确定自己 Mac 是哪种芯片：左上角 → 关于本机，「芯片」写 Apple M 开头的选 aarch64，写 Intel 的选 x64。

**macOS：** 打开 dmg，把智票拖进「应用程序」。

> ⚠️ **第一次打开要用右键。** 安装包没有 Apple 签名，直接双击会提示「无法验证
> 开发者」。**右键点智票 → 打开 → 再点一次「打开」**，只需要做这一次，之后
> 双击就正常了。详见 [15. 疑难排查](#15-疑难排查)。

**Windows：** 双击 exe，按提示安装。默认装到当前用户目录，不需要管理员权限。

> ⚠️ 如果出现「Windows 已保护你的电脑」，点「更多信息」→「仍要运行」。同样是因为
> 安装包未做代码签名。

### 2.3 卸载

- **macOS：** 把「应用程序」里的智票拖到废纸篓
- **Windows：** 设置 → 应用 → 智票 → 卸载

卸载**不会**删除你的发票数据。数据位置见 [13.1](#131-数据存在哪)，需要彻底清除请手动删除该目录。

### 2.4 更新

智票启动时会检查更新。有新版本时会提示，确认后自动下载安装。

### 3.2 配色的含义

界面刻意保持安静，颜色只用在需要人处理的地方：

| 颜色   | 含义                                           |
| ------ | ---------------------------------------------- |
| 琥珀色 | 待复核 —— 某个字段识别得不够确定，需要你看一眼 |
| 红色   | 校验错误或疑似重复 —— 这是实实在在的问题       |
| 无颜色 | 一切正常                                       |

正常的发票**状态列是空的**——不显示绿色对勾。一屏都是绿色等于没有信息，而空白让仅有的几个琥珀色和红色标记一眼就能找到。

## 4. 五分钟快速上手

1. **打开智票**，把这个月的发票文件（或整个文件夹）拖进窗口。
2. **等导入完成。** 进度面板会实时显示：已导入 / 待复核 / 重复 / 失败。
3. **点左侧「待复核」**，逐张检查。每张的问题字段会高亮，改完点「标记已复核」。
   - 没有待复核？直接跳到第 5 步。
4. **点左侧「疑似重复」**（如果有数字），确认这些票是不是真的重复报销了。
5. **点左侧「报销单」→ 新建**，填标题和申请人，勾选这个月要报的发票。
6. **点「导出」**，选保存位置。完成。

## 5. 导入发票

### 5.1 三种导入方式

| 方式       | 怎么做                                                           |
| ---------- | ---------------------------------------------------------------- |
| 拖拽       | 把文件或文件夹拖到窗口**任何位置**                               |
| 选择文件   | 点左上角「导入发票」→「选择文件」                                |
| 选择文件夹 | 点「导入发票」，在弹出的选择里点「选择文件夹」，会递归读取子目录 |

### 5.2 支持的格式

| 格式     | 典型来源                                               | 识别效果                                        |
| -------- | ------------------------------------------------------ | ----------------------------------------------- |
| **PDF**  | 开票方邮件、微信、税局下载                             | 最好。多数能 100% 准确离线读出                  |
| **OFD**  | 税局平台、部分开票系统                                 | 最好。OFD 是国标版式文件，字段是真文本          |
| **XML**  | 数电票原始文件                                         | 最好。这就是发票本身                            |
| **图片** | 纸质票拍照/扫描（jpg / png / bmp / webp / tif / heic） | 取决于二维码是否清晰，见 [第 6 节](#6-识别原理) |
| **ZIP**  | 邮件里整包下载的发票                                   | 自动解压，逐张导入                              |

### 5.3 导入结果的四种状态

| 状态         | 含义                                   | 要做什么                         |
| ------------ | -------------------------------------- | -------------------------------- |
| **已导入**   | 关键字段全部读出且可信                 | 不用管                           |
| **待复核**   | 读出了一部分，但某些字段不够确定       | 去「待复核」里确认               |
| **重复文件** | 这个**文件**之前导入过（内容完全一样） | 不用管，这不是错误               |
| **识别失败** | 没能读出发票号码和金额                 | 仍然存进了库里，可以手动补录字段 |

> **「重复文件」不是错误。** 它只是说你把同一个文件拖进来了两次——比如同一个文件夹导入了两遍。真正需要注意的重复叫「疑似重复」，见 [第 9 节](#9-重复报销检测)。

> **「识别失败」的文件不会丢。** 它照样在列表里，只是字段是空的，你可以打开详情手动填。这样至少不会漏掉一张票。

### 5.4 导入完成后

结果面板会列出**没有干净导入的那些文件**，每一条可以展开看「识别过程」——智票试了哪几层、哪层读出了什么、哪层没读到。这是理解「为什么这张没读出来」最直接的办法。

如果有照片类文件因为 AI 识别未开启而没读出来，面板底部会出现一条提示。是否开启由你决定，见 [第 12 节](#12-ai-识别设置)。

## 6. 识别原理

理解这一节，你就能预判哪些票会读得准、哪些需要人工确认。

### 6.1 分层识别

智票 **不是**一上来就 OCR。它按可靠程度从高到低依次尝试：

```
文件
 │
 ├─ ① 发票 XML ────────────────────────── 权威，直接结束
 │     数电票 PDF 常内嵌原始 XML；OFD 包里也有附件。
 │     这不是"识别"出来的，这就是税局开具的发票数据本身。
 │
 ├─ ② 二维码 ──────────────────────────── 精确
 │     每张增值税发票左上角都有。它带纠错和校验，
 │     要么解出完全正确的号码/日期/金额，要么解不出来。
 │     不存在"解出了一个差不多的错数字"这种中间状态。
 │
 ├─ ③ PDF 文本层 / OFD 版面文本 ────────── 高
 │     电子发票是软件生成的 PDF，字段是真正的文本，
 │     不是图片。离线、免费、精确。
 │
 └─ ④ AI 视觉识别 ────────────────────── 仅供参考，默认关闭
       只有前三层都读不出的照片才会走到这一步。
```

### 6.2 为什么不直接上 OCR

因为 **OCR 出错的方式是"自信地给你一个错答案"**。

一张歪着拍、有阴影的照片，OCR 引擎可能把 `8` 认成 `3`，然后毫无异样地返回给你。这个错误的发票号码会：

- 通过所有位数检查（看起来完全合法）
- 让重复报销检测失效（号码不一样了，比对不上）
- 从此再没人看第二眼

而二维码要么解出来（内容一定是对的），要么解不出来（你会知道）。所以照片的识别顺序是**先解二维码，解不出来才考虑 AI**。

### 6.3 扫描件 PDF 怎么处理

扫描件 PDF 没有文本层，但它内部藏着一张完整的图片——扫描仪存进去的原始 JPEG。智票直接从 PDF 的对象结构里把这张图取出来，交给二维码解码器和 AI。

这比"渲染 PDF 再识别"更好：没有重新压缩这一步，图像质量是原始的。同时也让安装包省下了一个 PDF 渲染引擎（每平台约 4MB）。

### 6.4 每个字段都记着来源

智票为**每一个字段**单独记录：它是从哪一层读到的，有多可信。

| 来源       | 可信度 | 界面显示   |
| ---------- | ------ | ---------- |
| 发票 XML   | 100%   | 发票 XML   |
| 人工录入   | 100%   | 人工录入   |
| 二维码     | 95%    | 二维码     |
| PDF 文本层 | 90%    | PDF 文本层 |
| AI 识别    | 75%    | AI 识别    |

低于 90% 的字段会在详情里高亮，并计入「待复核」。

**这是这个软件的核心承诺：它不会悄悄给你一个它自己都不确定的金额。**

### 6.5 更好的来源永远不会被覆盖

如果二维码已经解出了发票号码，AI 后来读出一个不同的号码，**以二维码为准**。同理，人工录入的值优先级最高，重新识别也不会覆盖掉你手动改过的字段。

## 7. 复核与更正

### 7.1 什么叫「待复核」

同时满足这两个条件的发票会进「待复核」：

1. 关键字段可信度低于 90%，**或者**存在校验问题
2. 你还没点过「标记已复核」

来源可靠、没有问题的发票不会打扰你，哪怕你从没打开过它。

### 7.2 详情面板

点任意一行打开右侧详情面板。里面有：

- **可编辑的全部字段**，每个字段旁标注来源；不确定的字段会用琥珀色边框高亮
- **校验问题清单**（如果有）
- **明细项目**（货物或服务名称、数量、单价、金额、税率、税额）
- **识别过程**：试了哪些层、结果如何
- **原文件**：路径，以及「打开原文件」按钮——核对最快的办法就是把原票调出来看一眼
- **分类**：当前类别、是哪条规则判的、可以改

### 7.3 键盘操作

复核一个月的发票不需要碰鼠标：

| 按键      | 作用            |
| --------- | --------------- |
| `↑` / `↓` | 上一张 / 下一张 |
| `Esc`     | 关闭详情面板    |

### 7.4 校验问题一览

| 问题                                   | 含义                          | 怎么办                                                                                                                   |
| -------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **价税合计对不上**                     | 金额 + 税额 ≠ 价税合计        | 这三个数里至少有一个读错了。打开原票核对，改正后问题自动消失。**这是最有价值的一条检查**——任何一个数字读错一位都会触发它 |
| **发票号码位数异常**                   | 数电票应为 20 位，其他为 8 位 | 多半是识别时丢了或多了一位，对着原票改                                                                                   |
| **开票日期无法识别**                   | 日期格式不合法                | 手动填成 `YYYY-MM-DD`                                                                                                    |
| **开票日期晚于今天**                   | 未来日期                      | 通常是年份读错了                                                                                                         |
| **缺少发票号码 / 开票日期 / 价税合计** | 没读出来                      | 手动补录，或用「重新识别」再试一次                                                                                       |

> 红色是硬错误（金额算不平、日期非法），琥珀色是提醒。

### 7.5 手动更正

直接在详情面板里改。改过的字段会标记为「人工录入」，**优先级最高**——以后再怎么重新识别都不会被覆盖。

金额请填人民币元，例如 `1060.00`。填不合法的内容会被拒绝，而不是悄悄存成 0。

### 7.6 重新识别

「重新识别」会重新读一遍原文件。典型用途：导入时 AI 识别是关的，后来开启了，想把当初读不出的照片再试一次。

你手动改过的字段不会被覆盖，只会补上空缺的部分。

## 8. 费用分类

### 8.1 规则怎么工作

智票用**规则**而不是 AI 来分类。原因很实在：同样二十家供应商每个月都会出现，一条三月份判对的规则十一月份照样对——免费、离线、瞬间完成，而且**每次结果都一样**。

一个模型对同一个问题两次可能给出两个答案。在一张需要和上个月对账的表里，那是缺陷，不是灵活。

### 8.2 规则的结构

一条规则 = 一个**类别** + 若干**条件** + 一个**优先级**。

- 同一条规则内的多个条件是 **且**（全部满足才算匹配）
- 同一个类别可以有多条规则，它们之间是 **或**
- 多条规则同时匹配时，**优先级高的胜出**

### 8.3 匹配字段，按可靠程度排序

| 字段             | 说明                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **税收分类简称** | 发票项目名称里 `*星号*` 之间的部分，例如 `*住宿服务*住宿费` 里的「住宿服务」。**这是全国统一的税局分类，由开票方从固定清单里选，最可靠。** |
| 项目名称         | 完整的货物或服务名称                                                                                                                       |
| 票种             | 铁路电子客票、出租车票等——票种本身就说明了用途                                                                                             |
| 备注             | 发票备注栏                                                                                                                                 |
| 销售方名称       | 开票公司名。最容易误伤（"某某大酒店"开的可能是餐饮发票），所以内置规则里它的优先级最低                                                     |

> **记住 `*星号*` 这一条，胜过记住其他所有内容。** 一条 `税收分类简称 包含 住宿服务` 的规则，能覆盖全中国所有酒店，而 `销售方名称 包含 酒店` 只能覆盖名字里带"酒店"两个字的那些。

### 8.4 优先级分档

内置规则用这几档，你自己加规则时照着来即可：

| 优先级 | 用途                       |
| ------ | -------------------------- |
| 200    | 你采纳 AI 建议后生成的规则 |
| 150    | 按税收分类简称匹配         |
| 120    | 按项目名称匹配             |
| 100    | 按票种匹配                 |
| 50     | 按销售方名称兜底           |

优先级不只影响结果，也影响详情里显示的「为什么是这个类别」——应该让用户看到最具体的那个理由。

### 8.5 内置类别

住宿 · 餐饮 · 市内交通 · 长途交通 · 办公用品 · 通讯费 · 软件与服务 · 快递邮寄 · 会议费 · 油费 · 过路过桥费 · 培训费 · 广告宣传 · 房租物业 · 未分类

在规则里输入一个新类别名，这个类别就存在了。

### 8.6 编辑规则

左侧「分类规则」。规则按类别分组，每条以中文句子显示（如「税收分类简称 包含 住宿服务」），一眼就能看懂为什么某张票被归到某类。

改完规则后点「**重新分类全部发票**」，改动会应用到已经导入的发票上。**你手动指定过类别的发票不会被规则覆盖**——手动决定优先于规则。

### 8.7 恢复内置规则

删错了规则可以「恢复内置规则」，它只会**补回缺失的**内置规则，不会覆盖你改过的任何东西。

升级 App 也不会偷偷把你删掉的规则加回来。

### 8.8 AI 建议分类

规则全都没匹配上时，打开发票详情，在「AI 建议分类」里点「**问一次**」（需要
先在设置里开启，见 [12.3](#123-两个独立开关)）。

它返回三样东西：

1. 建议的类别
2. 一句话理由
3. **一条可以保存的规则**（写成「税收分类简称 包含 住宿服务」这样的人话）

然后有两个按钮：

| 按钮           | 作用                                           |
| -------------- | ---------------------------------------------- |
| **只用于这张** | 只把类别设到当前这张发票上，不留规则           |
| **保存为规则** | 把那条规则存下来，并对已导入的发票重新归类一遍 |

**「保存为规则」才是重点。** 存下来之后，以后同类发票再也不需要问 AI ——
每存一条，就少一笔长期开销。只用一次的话，下个月同一家供应商还要再问一遍。

## 9. 重复报销检测

这是智票最值钱的功能，也是「保存一份本地账本」的全部理由。

### 9.1 两种「重复」

| 类型         | 判定依据                            | 严重程度       | 处理                     |
| ------------ | ----------------------------------- | -------------- | ------------------------ |
| **重复文件** | 文件内容的 SHA-256 完全相同         | 不是问题       | 自动忽略，不会产生第二行 |
| **疑似重复** | 两张不同的文件，发票代码 + 号码相同 | **需要你判断** | 两行都保留并互相标记     |

### 9.2 为什么是「发票代码 + 号码」

数电票的 20 位号码是全国唯一的，但**旧版发票的 8 位号码不是**——不同开票方的号码可能重复，必须连同发票代码一起比对。只看号码会天天误报。

### 9.3 为什么不直接拦截

因为你需要**看到两行**才能判断：

- 是同一张票被导入了两次（不同文件名、不同来源，比如邮件里一份、微信里一份）→ 删掉一份
- 是真的已经报销过了 → 从这次报销单里去掉
- 是误报 → 忽略

自动删掉一份，你就永远不知道发生过什么。

### 9.4 检测范围是整个账本

不只是这一张报销单，而是**你导入过的所有发票**。这才能抓住「这张票上个月已经报了」这种情况——也正是最容易出事的情况。

导出报销单之前，预览页会**再检查一次**。

## 10. 报销单与导出

### 10.1 新建报销单

左侧「报销单」→ 新建。填写：

| 字段     | 说明                      |
| -------- | ------------------------- |
| 标题     | 例如「2024年3月差旅报销」 |
| 申请人   | 你的名字                  |
| 部门     |                           |
| 制表日期 | 默认今天                  |
| 说明     | 备注，可留空              |

### 10.2 加入发票

报销单页面分成三段：**表头信息**（标题、申请人等）、**选择发票**、**核对与导出**。

选择发票那一段是左右两个列表：

- 左边「**候选发票**」是还没加进这张单的发票，可以按关键词、类别、起止日期
  筛选，也有「本月 / 近三个月」的快捷选项。勾选后点「**加入报销单**」。
- 右边「**已在这张单上**」是当前这张单的内容。每行可以上移、下移、
  「**从报销单移出**」（只是移出，不会删除发票本身），也可以一键
  「按开票日期从早到晚排序」。

**顺序会原样保留到导出的表里**，所以想让财务按日期看就先排一下序。

一张发票可以出现在多张报销单里（智票不阻止），但那正是「疑似重复」要提醒你的场景。

### 10.3 预览

导出前一定会先看预览：

- 张数、金额（不含税）、税额、价税合计
- **合计金额大写**（如「壹仟零陆拾圆整」）——中国报销单必填项，会自动生成
- 其中**可抵扣进项税额**——只有专用发票的税额计入，普通发票不能抵扣
- 分类汇总，含占比
- ⚠️ **校验问题**：哪张票的金额算不平
- 🔴 **疑似重复**：哪张票在账本里还有另一份

导出按钮在这些警告**下面**，位置是刻意的：一张价税合计对不上的表交到财务手里，正是这个软件存在的意义所在——在那之前发现它。

### 10.4 导出通用 Excel

生成一个 `.xlsx`，包含两个工作表：

**报销明细**

| 序号 | 开票日期 | 发票号码 | 票种 | 销售方名称 | 费用类别 | 金额(不含税) | 税额 | 价税合计 | 可抵扣 | 备注/问题 |
| ---- | -------- | -------- | ---- | ---------- | -------- | ------------ | ---- | -------- | ------ | --------- |

表头有申请人、部门、制表日期；表尾有合计行和大写金额。有校验问题的行，问题会以红色写在最后一列——**问题会跟着表一起交出去，而不是被丢掉**。

**分类汇总**

按费用类别汇总金额、税额、张数、占比，末尾单列「其中可抵扣进项税额」。

所有金额都是**真正的数字单元格**，可以直接 `SUM`，不是看起来像数字的文本。

## 11. 公司模板

如果你公司有固定的报销单模板，智票可以直接填进去，**完整保留公司的字体、边框、表头、公章位置**。

### 11.1 原理

`.xlsx` 本质是一个装满 XML 的 zip。智票只替换单元格里的占位符文字，其他一个字节都不动——所以样式、图片、合并单元格、打印设置全部原样保留。

### 11.2 制作模板：三步

**第一步**，打开你公司的报销单模板。

**第二步**，把占位符填到对应单元格里：

| 占位符           | 填入内容           |
| ---------------- | ------------------ |
| `{{标题}}`       | 报销单标题         |
| `{{申请人}}`     | 申请人姓名         |
| `{{部门}}`       | 部门               |
| `{{日期}}`       | 制表日期           |
| `{{说明}}`       | 备注说明           |
| `{{张数}}`       | 发票张数           |
| `{{不含税}}`     | 合计金额（不含税） |
| `{{税额}}`       | 合计税额           |
| `{{合计}}`       | 价税合计           |
| `{{合计大写}}`   | 价税合计的中文大写 |
| `{{可抵扣税额}}` | 其中可抵扣进项税额 |

**第三步**，在明细表格的**第一个数据行**填入明细占位符：

| 占位符            | 填入内容       |
| ----------------- | -------------- |
| `{{明细.序号}}`   | 序号           |
| `{{明细.日期}}`   | 开票日期       |
| `{{明细.号码}}`   | 发票号码       |
| `{{明细.票种}}`   | 票种           |
| `{{明细.销售方}}` | 销售方名称     |
| `{{明细.类别}}`   | 费用类别       |
| `{{明细.不含税}}` | 金额（不含税） |
| `{{明细.税额}}`   | 税额           |
| `{{明细.合计}}`   | 价税合计       |
| `{{明细.问题}}`   | 校验问题       |

**只需要填一行。** 含有任何 `{{明细.*}}` 的那一行是「明细模板行」，导出时会按发票数量复制成 N 行，**每一行都带着这一行原有的格式**，下面的内容自动下移。

### 11.3 示例

模板长这样：

```
┌──────────────────────────────────────────────────┐
│              {{标题}}                             │  ← 公司抬头样式
├─────┬──────────┬────────────┬──────────┬─────────┤
│申请人│{{申请人}} │   部门     │ {{部门}}  │{{日期}} │
├─────┼──────────┼────────────┼──────────┼─────────┤
│序号 │ 开票日期 │  销售方    │  类别    │  金额   │
├─────┼──────────┼────────────┼──────────┼─────────┤
│{{明细.序号}}│{{明细.日期}}│{{明细.销售方}}│{{明细.类别}}│{{明细.合计}}│  ← 只写这一行
├─────┴──────────┴────────────┼──────────┼─────────┤
│            合计             │{{张数}}张 │{{合计}} │
├─────────────────────────────┴──────────┴─────────┤
│  金额大写：{{合计大写}}                            │
└──────────────────────────────────────────────────┘
```

导出 12 张发票，明细行自动变成 12 行，合计行和大写行下移 11 行。

### 11.4 导出后的提示

导出完成会告诉你**哪些占位符模板里没有**。这不是错误——公司表没有「可抵扣税额」这一栏就是不需要——但你应该在把表发给财务之前看到这个清单，而不是之后才发现少了一列。

### 11.5 模板注意事项

- 占位符要**独占一个单元格**才会变成数字。写在句子里（如 `申请人：{{申请人}}`）也可以，但结果是文本。
- 金额类占位符独占单元格时会写成**数字**，可以被 `SUM` 统计。
- 模板会记住，下次导出不用重新选。
- 只处理**第一个工作表**。

## 12. AI 识别设置

### 12.1 什么时候需要 AI

**电子发票（PDF / OFD / XML）完全不需要 AI。** 它们走离线路径，免费、精确、瞬间完成。

只有**纸质发票的照片**，并且**二维码没解出来**时，AI 才会介入。

### 12.2 默认是关闭的

这是一个刻意的产品决定，不是谨慎过度。开启意味着发票图片——上面有购买方名称、税号、金额——会离开你的电脑。这个选择应该由你明确做出，而不是由软件替你默认。

### 12.3 两个独立开关

它们发送的内容完全不同，所以是两个开关：

| 开关            | 发送什么                              | 不发送什么                     |
| --------------- | ------------------------------------- | ------------------------------ |
| **AI 识别照片** | 发票图片（缩放到长边 1600px 的 JPEG） | ——                             |
| **AI 建议分类** | 票种、销售方名称、项目名称、备注      | **金额、税号、购买方一律不发** |

你完全可以只开第二个：让 AI 帮你判断「滴滴出行」算哪一类，同时拒绝上传任何发票图片。

### 12.4 服务商

只收录国内厂商——境外接口在国内网络下多数连不上，而且国产视觉模型恰好是在中文票据上训练的。

| 服务商                     | 视觉模型             | 说明                                  |
| -------------------------- | -------------------- | ------------------------------------- |
| **阿里云百炼（通义千问）** | `qwen-vl-ocr`        | **推荐**。有专门做文档 OCR 的型号     |
| 智谱 GLM                   | `glm-4v-flash`       | 有免费额度                            |
| 火山方舟（豆包）           | `doubao-vision`      | 模型要填自己的接入点 ID（`ep-` 开头） |
| 月之暗面 Kimi              | `moonshot-v1-vision` |                                       |
| 阶跃星辰 StepFun           | `step-1v`            |                                       |
| 腾讯混元                   | `hunyuan-vision`     |                                       |
| MiniMax                    | `MiniMax-VL`         |                                       |
| 硅基流动                   | `Qwen2.5-VL`         | 聚合平台，可用开源 Qwen-VL            |
| DeepSeek                   | 无                   | **不能识别图片**，只能做分类建议      |
| Ollama（本机）             | 取决于你拉的模型     | 完全离线，图片不出本机                |
| 自定义接口                 | 自己填               | 需兼容 OpenAI Chat Completions        |

### 12.5 配置步骤

左侧「设置」→「AI 识别」，页面自上而下分三张卡片：

1. **发送到 AI 的内容** —— 两个开关在最上面，因为这是你真正要做的决定；
   下面的服务商和模型都是为它服务的。先别急着打开。
2. **服务商** —— 选一家，点它的控制台链接去申请 API Key，粘进「API Key」栏
   （只能写入、读不出来，右边会显示「已配置」）。然后点「**测试连接**」，
   成功会告诉你可用模型有几个，失败会把服务商的原话直接显示出来。
3. **模型** —— 一般不用动。留空表示用默认（括号里会写出默认是哪个）。
   能列模型的服务商有「获取模型列表」按钮，不能的就直接从下拉里选，
   或者用「自定义…」自己填。

连接测通之后，再回到第一张卡片打开你需要的开关。

### 12.6 费用

一张发票 = 一张图片 + 几百个输出 token。按国内主流定价，**单张成本通常在一分钱以内**。一个月几十张的量，费用可以忽略。

分类建议只发几十个字，更便宜。

### 12.7 API Key 存在哪

存在配置目录下一个单独的文件里，权限 0600，**不和发票数据库放在一起**。

原因很实际：数据库是你可能会备份、拷到另一台电脑、或者发给同事的东西，密钥不该跟着一起走。

## 13. 数据与隐私

### 13.1 数据存在哪

| 平台    | 路径                                                                       |
| ------- | -------------------------------------------------------------------------- |
| macOS   | `~/Library/Application Support/com.chengaoshen.invoicedesk/invoicedesk.db` |
| Windows | `%APPDATA%\com.chengaoshen.invoicedesk\invoicedesk.db`                     |

一个 SQLite 文件，装着全部发票、分类规则和报销单。

### 13.2 备份与迁移

直接复制这个文件。换电脑时把它放到新机器的同一位置即可。

**建议定期备份。** 它是你几个月积累下来的账本和分类规则。

### 13.3 原始文件

智票 **不复制**你的发票原文件，只记录路径。所以：

- 数据库很小
- 但如果你把原文件挪走或删掉，「打开原文件」和「重新识别」会失效（已经读出来的字段不受影响）

建议把发票文件放在一个固定目录里。

### 13.4 金额是精确的

这一点值得单独说明，因为它是报销工具最容易出错、也最不该出错的地方。

智票 **全程用整数「分」表示金额**，从识别、存储、汇总到导出，中间不经过任何浮点数。

为什么重要：计算机的浮点数无法精确表示 `0.1`。用浮点做金额，`1.005 × 100` 会得到 `100.49999999999999`，四舍五入变成 ¥1.00——凭空少了一分钱，而且没有任何报错。一千笔 ¥0.07 用浮点累加，结果不等于 ¥70.00。

所以：

- 识别出的 `1060.00` 直接解析成整数 `106000` 分，不走 `parseFloat`
- 汇总、分类合计、报销单合计全部是整数加法，不会累积误差
- 导出到 Excel 时，单元格里写的数字是由整数分直接算出的十进制字符串，不是浮点数格式化的结果
- 你在详情里手动输入的金额同样按整数解析；输入不合法时会被拒绝，而**不会**悄悄存成 0

换句话说：**导出的表里那个数字，和账本里存的数字，是同一个数字。**

### 13.5 联网行为

智票只在两种情况下联网：

1. 你开启的 AI 功能实际被触发时
2. 检查应用更新

除此之外没有任何网络请求。没有遥测，没有统计上报，没有账号。

## 14. 常见问题

**Q：一张 PDF 显示「识别失败」，可原文件明明能打开看到内容。**

这是扫描件——PDF 里装的是一张图片，没有文本层。看详情里的「识别过程」确认。这种情况需要二维码清晰，或者开启 AI 识别。

**Q：为什么专用发票的金额栏读出来比票面小？**

不是读错。专用发票二维码里存的是**不含税金额**，普通发票存的才是价税合计。智票知道这个区别，会把专票的值放进「金额（不含税）」而不是「价税合计」。价税合计会由「金额 + 税额」推算出来，或者从文本层读。

**Q：火车票/飞机行程单没有税额，会不会导致合计对不上？**

不会。这类票据不做税额拆分，智票把全额当作不含税金额，明细列的合计仍然等于总计。

**Q：能同时管理多个人的报销吗？**

可以，一个账本里放所有人的发票，用不同的报销单区分，报销单上填不同的申请人。查重是跨全库的，正好能发现两个人报了同一张票。

**Q：改了分类规则，已经导入的发票会自动更新吗？**

不会自动，需要点「重新分类全部发票」。手动指定过类别的发票不会被覆盖。

**Q：能不能不用 AI 只用离线功能？**

完全可以，而且这是默认状态。电子发票 100% 走离线路径。只有纸质票照片会受影响——二维码清楚的照片离线也能读出号码、日期、金额。

**Q：支持增值税专用发票的进项税抵扣统计吗？**

支持。汇总表里有「其中可抵扣进项税额」，只统计专用发票（含数电专票）的税额。

**Q：识别出来的字段可以批量导出吗？**

可以，导出通用 Excel 就是全部字段的明细表。

**Q：合计金额会不会有一分钱的误差？**

不会。金额全程按整数「分」处理，不经过浮点数，详见 [13.4](#134-金额是精确的)。导出的 Excel 里金额是**真正的数字单元格**，可以直接用 `SUM` 统计，不是看起来像数字的文本。

## 15. 疑难排查

### macOS 提示「无法打开，因为无法验证开发者」

**这是预期内的，安装包没有问题。** 智票目前没有购买 Apple 开发者证书，发布的
是未签名的 dmg，所以 Gatekeeper 第一次会拦下来。

绕过办法（只需要做一次）：

1. 在「应用程序」里找到智票
2. **右键**点它 → 选「打开」（不要双击）
3. 弹窗里再点一次「打开」

之后就和普通应用一样双击即可。

> 如果右键「打开」里没有该选项，可以到「系统设置 → 隐私与安全性」，在页面下方
> 会看到「已阻止智票…」，点「仍要打开」。

### Windows 提示「Windows 已保护你的电脑」

点「更多信息」→「仍要运行」。这是 SmartScreen 对新发布应用的常规提示，随着下载量积累会消失。

### 拖文件进去没反应

- 确认拖的是文件不是网页链接
- 试试用「导入发票」按钮选择
- 检查文件扩展名是否在支持列表里

### 导入很慢

- 扫描件 PDF 要抽取内嵌图片，比电子发票慢
- 开启了 AI 识别时，每张需要识别的照片都要等一次网络往返
- 电子发票的导入应该是瞬间完成的；如果不是，可能是文件在网络盘上

### 「测试连接」失败

| 错误提示             | 通常原因                                                              |
| -------------------- | --------------------------------------------------------------------- |
| 还没有配置 AI 服务商 | 没填 API Key                                                          |
| 连接失败：401 / 403  | Key 错了或已失效                                                      |
| 连接失败：超时       | 网络问题，或选了国内访问不了的接口                                    |
| 连接失败：404        | 自定义接口的地址填错了（应填到 `/v1` 为止，不含 `/chat/completions`） |

### AI 识别报「模型没有返回 JSON」

换一个模型试试。有些通用对话模型不擅长严格按格式输出，视觉专用型号（如 `qwen-vl-ocr`）稳定得多。

### 金额显示为 0 或空

说明没读出来。打开详情手动填，或对着原票核对后录入。智票宁可留空也不会猜一个金额。

## 16. 附录

### 16.1 术语表

| 术语             | 说明                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| **数电票**       | 全面数字化的电子发票。号码 20 位，**没有发票代码**，2021 年起逐步推行 |
| **发票代码**     | 旧版发票的 10 或 12 位编码，与 8 位号码一起唯一标识一张发票           |
| **价税合计**     | 含税总金额，也就是实际报销的数字                                      |
| **税收分类简称** | 发票项目名称里 `*星号*` 之间的部分，全国统一分类                      |
| **进项税额抵扣** | 企业可以从应缴增值税中扣除的部分。**只有专用发票可以**                |
| **OFD**          | GB/T 33190 国家标准版式文档格式，中国自主的 PDF 替代品                |
| **校验码**       | 增值税电子普通发票上的 20 位码，用于官方查验                          |
